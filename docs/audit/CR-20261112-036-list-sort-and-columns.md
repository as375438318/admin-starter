## 3. 两个关键实现约束（都已写进代码注释与断言 #101）

1. **`sortKey` 必须来自后端 `SORTS` 白名单**：后端对白名单外的 `sort` **静默回落**默认列、不报错，写错了表现为"点了表头没反应"。因此白名单在前端镜像一份，并有单测断言页面用到的每个 `sortKey` 都在镜像里。
2. **页面 fetcher 必须显式转发 `sort`/`order`**：本项目每个页面的 fetcher 是逐字段映射的（`userApi.page({ page, pageSize, keyword, ... })`），漏一行排序就永远不生效。**这是本期真实踩到的坑**——E2E 第一次跑就是"表头有箭头、请求没参数"。

## 4. 自身踩的坑（3 条）

| 坑 | 现象 | 处置 |
|---|---|---|
| E2E 用 `/system/user` 打不开页面 | 页面显示「页面不存在」 | 路由来自后端菜单，实际是复数 `/system/users` |
| 页面 fetcher 丢掉排序参数 | 表头图标能点，但请求里没有 `sort` | 3 个页面各补 `sort: params.sort, order: params.order`，并在注释里写明原因 |
| 单测对"旧偏好失效"的期望写错 | 期望隐藏 2 列，实际 1 列 | 用户已有显式偏好时 `defaultVisible` 不应再叠加——改成期望 1 列并断言 `createdAt` 变可见 |
