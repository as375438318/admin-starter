## 1. 背景

`AGENTS.md` §7 把"契约测试失败"列为阻断项，但契约测试只证明**响应形状**对，不证明**业务判断**对。`CR-20261111-004` 之后后端测试覆盖了数据权限与脱敏，业务逻辑里风险最高的一块仍是**通知投递**：

- 收件人算错 = 通知发给不该看到的人（数据泄露），或该看的人收不到（漏发）；
- 通知**发出后不可撤回**（`revoke` 只是标记），错误无法通过重跑修复；
- 这块目前只有 2 个事务测试（`NotificationPublisherTransactionTest`），只验证提交/回滚，不验证"发给谁"。

## 2. 范围

新增 `NotificationPublishTest`（system 模块，16 用例，全部 Mockito 隔离，无外部依赖）：

| 分组 | 用例 | 锁定的行为 |
|---|---|---|
| 入参校验 | 4 | 标题空/超 200 字、内容空、范围为空、范围类型非法（TEAM）、指定范围缺目标 ID |

## 4. 测试过程中确认的两条真实语义（我最初的假设是错的）

1. **ALL 与其它范围是并集，不是"ALL 吞掉其余"**：`normalizeScopes` 用 `scopeType:targetId` 做去重键，ALL 只是其中一个键；`resolveRecipients` 对所有范围取并集。我最初断言"带 ALL 时其它范围被忽略"，测试红掉后按实现修正，并补了一条更有价值的断言。
2. **带 ALL 时其它范围的目标仍会被校验**：`validateTarget` 在去重之前逐条执行，所以"ALL + 不存在的用户"会直接报错而不是静默放过。这是更好的 fail-closed 行为，已固化为测试。
