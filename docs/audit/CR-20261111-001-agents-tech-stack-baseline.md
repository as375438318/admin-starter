## 1. 背景

`AGENTS.md` §9 的两张表自脚手架交付起一直为空：

- §9-A（项目约束）为空 → 按 §9 自身规定「没有 A 不得进入方案讨论」，但项目已开发到 Flyway V16，属**流程与现状背离**；
- `AGENTS.md` §9-B（技术选型）为空 → `FE-STACK-001`（技术栈须在 `AGENTS.md` §9-B 确认后才开工）、`FE-STACK-004`（包管理器由 `AGENTS.md` §9-B 选定且唯一）无法满足，已在 `impl-notes.md` 登记为 `RISK-ACCEPTED` 与 `RULE-GAP`（见 CR 前基线）。
- 后果：所有文档只能「引用 `AGENTS.md` §9-B」，但该节没有内容，技术栈事实上处于**无定义方**状态，与 `AGENTS.md` §1「本节是技术栈唯一定义方」自相矛盾。

## 2. 范围

**改**：

- `AGENTS.md` §9-A 六个字段、§9-B 九行选型结论 + 依据 ADR。
- 新增 `docs/decisions/ADR-005-tech-stack-baseline.md`（技术栈选型的决策记录与备选方案）。
- `docs/specs/INDEX-facts.md` + `docs/specs/facts.yaml` 新增事实「技术栈版本与选型」（技术栈从"无定义方"变为有唯一 owner）。
- **`README.md` 去掉技术栈版本号**：`AGENTS.md` §1 规定「`README.md` 只引用 `AGENTS.md` §9-B，不写版本号」，此前因该节为空，README 只能自带版本；该节填实后此写法即成违规。`docs/specs/backend-spec.md`、`docs/specs/frontend-spec.md` 已于 v1.6 起改为引用，无需再动。

**不改**：任何业务代码、接口、表结构、权限码、错误码、配置项；`docs/specs/` 其余四份规范正文。
