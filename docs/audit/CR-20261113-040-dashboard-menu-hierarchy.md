## 1. 问题是什么

V18 要新增权限码 `system:dashboard:view`，但工作台是**固定路由**（`router/index.ts` 里写死 `/dashboard`），
菜单树里没有对应页面节点可挂，于是迁移脚本把该 F 型（按钮）节点**直接挂到了「系统管理」目录（M）下**。

数据库实况（修复前）：

```
id=74  查看仪表盘统计  F  parent=1(系统管理 M)  sort=0
```

后果：
1. 菜单管理里出现一条「按钮挂在目录下」的孤儿节点，且 `sort=0` 让它排在所有页面之上（用户截图红框处）；
2. 角色授权树里它看起来像"目录级权限"，与其它"页面下的按钮"不一致；
3. 全库**仅此一例**（其它 F 节点都挂在 C 型页面菜单下）—— 属异常形态而非约定。

## 2. 怎么修

| 层 | 改动 |
|---|---|
| 数据（`V19__fix_dashboard_menu_hierarchy.sql`） | ① 新增**隐藏的 C 型页面菜单**「工作台」（`path=/dashboard`、`component=dashboard/index`、`permission_code=NULL`、`is_visible=0`、`sort=0`）；② 把 F 节点挪到该菜单下（`sort=1`）；③ 容器菜单授给所有在用角色（它无权限码，不构成提权，但不授权会让授权树出现"子授父未授"的悬空状态） |
| 前端（`router/index.ts`） | 动态路由新增**按 path 去重**：与固定路由同 path 的菜单路由不注册（原来是只按 name 去重，而菜单路由名是 `Menu{id}`，拦不住） |

### 两条关键约束（写进迁移注释与断言）

1. **容器菜单的 `permission_code` 必须为 NULL**：工作台页面本身对所有登录用户开放，只有"统计区"需要 `system:dashboard:view`。若给容器菜单配权限码，前端菜单路由会带上 `meta.permission`，普通用户打开首页直接 403。
2. **必须先有 path 去重**：否则菜单路由与固定路由都会注册出 `/dashboard`，后注册者覆盖前者。

## 5. 教训

给"固定路由页面"补权限码时，**不能随手挂到目录下**：权限码体系依赖菜单树，挂错层级会让菜单管理与授权树同时出现畸形节点。正确做法是给该页面补一个（可隐藏的）页面级菜单承载它的按钮权限。
