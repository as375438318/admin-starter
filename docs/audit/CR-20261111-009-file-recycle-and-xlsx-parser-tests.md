## 1. 背景

两块此前零测试，且都属于"出错不可逆"：

- **文件回收站**：文件按 SHA-256 去重共享字节，彻底删除时"是否删物理文件"的判断错一次就会把别人的文件变成空壳；删除/恢复还必须对"不存在"和"无权"表现一致（不泄露存在性）。
- **xlsx 解析**：行号错用户找不到问题行；空行没跳过会报一堆"第 N 行为空"；坏文件不兜底会抛 500。

## 2. 范围（+17 用例）

### `FileRecycleTest`（10，system）

| 用例 | 锁定 |
|---|---|
| 删除不存在/不可见记录 | 静默成功（幂等，不暴露存在性） |
| 删除可见记录 | 移入回收站并记录操作人 |
| 无登录上下文删除 | 不 NPE（系统任务调用路径） |
| 恢复不在回收站 | 幂等成功，不动文件 |
| 恢复在回收站 | 记录恢复，不动物理文件 |
| 彻底删除不存在的记录 | 幂等成功，不碰物理文件 |
| **仍有其它记录引用同一 `storage_path`** | **保留物理字节**（去重共享） |
| 无其它引用 | 删物理字节 |
| **执行顺序** | **先删行 → 再计数 → 最后删字节**（InOrder 断言；顺序反了会删掉仍被引用的字节） |
| 删除范围 | 只按被删记录的精确 `storage_path`，绝不递归删除 |

### `ExcelStreamParserTest`（7，system，用 POI 生成内存 xlsx 作夹具）

| 用例 | 锁定 |
|---|---|
| 正常解析 | 表头去必填星号（`任务标题*` → `任务标题`）、按表头映射、**保留 Excel 真实行号** |
| 空行 | 跳过空行，但后续行号仍是真实行号（否则用户按提示找不到行） |
| 空白字符行 | 整行只有空格也视为空行 |
| 多填的列 | 超出表头范围忽略，不让整行失败 |
| 数据页名不匹配 | 提示里带出期望页名，不是笼统"解析失败" |
| 行数超上限 | 拒绝并说明上限 |
| 非 xlsx 内容 | 统一提示"请确认是有效的 .xlsx 模板"，不抛 500 |
