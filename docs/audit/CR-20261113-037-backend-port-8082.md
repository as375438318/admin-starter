`server.port` 没有引环境变量（如 `${APP_SERVER_PORT:8082}`）：那会新增一个配置键、要进 `config-registry.yaml` 与 `SL-CFG-001` 校验，属另一件事；本机改端口不需要这一层。

## 2. 顺带修掉一个真实陷阱（本次踩到）

改完 `vite.config.ts` 的代理目标后重启前端，代理**仍然**连 8080（`ECONNREFUSED 127.0.0.1:8080`）。根因：

- `apps/pc` 下存在 `vite.config.js` + `vite.config.d.ts`（11-12 由 `vue-tsc -b` 生成）；
- **Vite 的配置解析顺序里 `.js` 优先于 `.ts`**，所以真正的 `vite.config.ts` 被忽略；
- 这两个文件被 `.gitignore` 覆盖、未进版本库，`git status` 看不见，`pnpm build` 每次又把它们生成回来。

处置：删掉残留 + 把 `tsconfig.node.json` 的编译产物重定向到 `node_modules/.tmp/tsconfig-node`（`outDir`/`declarationDir`/`tsBuildInfoFile`），`composite` 保留（项目引用仍需要）。改完验证：`pnpm build` 通过，且**不再**在配置旁边生成 `.js`。

> 这条已登记断言 #102：**改 `vite.config.ts` 不生效时，先看同目录有没有 `vite.config.js`**。

## 4. 环境侧处置（非代码）

- 本机 `8080` 被另一个 java 进程（PID 16772，非本项目）占用 → 故改 8082；
- 项目依赖的 Redis（Windows 服务 `redisstarter`，6379）此前被停掉，启动后端前已重新拉起（TCP 6379 监听中），否则后端启动会因连不上 Redis 失败。
