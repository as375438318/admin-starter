| 项目 | 内容 |
|---|---|
| 提出人 | 用户 2026-11-12「模板表头为什么有的加粗有的没有加粗？」 |
| 执行人 | AI 编码助手 |

| 档位 | **A（微改）**：1 个类 + 1 条测试；接口、表结构、权限码、错误码均未变 |

## 1. 现象与真因

`CR-20261112-029` 为了"只有星号是红的"，把表头改成了富文本，但**只对必填列用了富文本**，非必填列仍是普通字符串：

| 列 | 上一版的写入方式 | 加粗来源 |
|---|---|---|
| `任务标题*`、`归属部门*` | `XSSFRichTextString` + 显式 `bold` 字体段 | **run 自己的字体** |
| `任务状态`、`负责人` | `XSSFRichTextString`（无字体段）→ 落到 `<si><t>` 普通共享串 | **单元格样式字体** |

两种"加粗来源"在 Excel 里表现不一致 → 用户看到"有的粗有的不粗"。

> 排查过程：先解包真模板看 `sharedStrings.xml`，必填列是 `<si><r><rPr><b val="true"/>…`，非必填列是 `<si><t>任务状态</t></si>`；四个表头单元格的样式索引都是 `s="1"`（`fontId=1` 含 `<b/>`）。也就是说**样式是对的，问题在富文本 run 与样式的优先级差异**。

## 2. 修复

`headerText()` 改为**所有列统一走富文本**：文字段一律 `applyFont(0, len, boldFont)`；必填列再把星号单独一段标红。

修复后实测（重新下载模板解包）：

```xml
<si><r><rPr><b val="true"/>…</rPr><t>任务标题</t></r><r><rPr><b val="true"/><color indexed="10"/>…</rPr><t>*</t></r></si>
<si><r><rPr><b val="true"/>…</rPr><t>任务状态</t></r></si>
<si><r><rPr><b val="true"/>…</rPr><t>归属部门</t></r><r><rPr><b val="true"/><color indexed="10"/>…</rPr><t>*</t></r></si>
<si><r><rPr><b val="true"/>…</rPr><t>负责人</t></r></si>
```

四个表头全部带 `<b val="true"/>`，加粗机制一致。

## 3. 测试

`ExcelTemplateWriterTest` 新增第 7 条 `allHeadersAreBoldRichText`：遍历表头每个单元格，断言

1. 值是富文本（`XSSFRichTextString`）；
2. 文字段有显式字体且 `getBold() == true`。

这条测试的价值是**防止有人"为了少写代码"把非必填列改回普通字符串**——那会重新引入本 bug。

## 5. 教训

"只给需要特殊格式的那一列用富文本"是**看起来最小改动、实际最危险**的做法：同一行表头出现两种渲染机制。要么整行统一富文本，要么整行统一普通串 + 单元格样式，不要混。
